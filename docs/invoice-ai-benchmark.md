# Invoice AI Benchmark

## Technical verification

- The committed baseline uses Laravel 13, PHP 8.5, Filament 5 and Livewire 4. The benchmark adds Laravel AI 1.4 and Google's official PHP ADC library.
- The [reference implementation at 779365e](https://github.com/alecgarcia/laravel-ai-vertex/tree/779365e16568d311a6ade38d16be3cf1951cbc27/src) demonstrates registering a provider with `Ai::extend`, resolving short-lived ADC tokens with an expiry margin, and extending the SDK Gemini gateway at its HTTP client boundary. Its router and GenerateContent gateway are unnecessary for this single-model benchmark. The local implementation uses these concepts with original application code.
- Laravel AI 1.4 already constructs Interactions requests with inline base64 image and PDF attachments and a JSON Schema response format. It also parses structured responses and usage. The benchmark uses the official `v1` Interactions API with the current EU residency hostname and a fixed `locations/eu` path. The [Interactions guide](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/capabilities/interactions/developer-guide) and [model capabilities](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/gemini/3-1-flash-lite) document the route, model and modalities. The SDK sends `store=false`, which the local gateway enforces.
- Gemini 3.1 Flash-Lite Standard non-global list rates are USD 0.275 per million uncached input tokens, 0.0275 per million cached input tokens and 1.65 per million output tokens, including thoughts. The [Google pricing table](https://cloud.google.com/model-garden/pricing) describes billing for PDFs as image input. Project-specific credits, discounts and actual billed cost are excluded.

## Local setup

1. Run `composer install`, `npm ci` and `npm run build`. In the PHP web and queue containers install `poppler-utils` and `zbar-tools` (Debian/Ubuntu package names). Poppler supplies `pdfinfo` and `pdftoppm`. The containers must share the same database, application key, cache and private storage volume. Set PHP and the proxy upload limit above 10 MiB to accommodate request overhead.
2. Add the settings in `.env.example` to the application's local `.env`. Set `INVOICE_AI_ENABLED=true` to show **Tools** in the user menu for Contiu super admins. Open **Invoice AI Benchmark** in that panel, or visit `/ferramentas` on the app host. Keep `INVOICE_AI_LIVE_ENABLED=false` for Demo and QR Only. `INVOICE_AI_PROVIDER=vertex`, `GOOGLE_CLOUD_LOCATION=eu` and `INVOICE_AI_MODEL=gemini-3.1-flash-lite` are the only supported settings.
3. Run `php artisan migrate`, start a worker with `php artisan queue:work --timeout=80` and run the Laravel scheduler. The queue reservation period must exceed the job timeout (the database default is 90 seconds). Restart workers after configuration changes. If the default filesystem is remote, configure `livewire.temporary_file_upload.disk` as `local` for the app. The benchmark refuses to start an upload unless Livewire uses Contiu’s private local disk. Keep temporary storage private and make the benchmark directory readable only by the application runtime.
4. Load a fixture in **Demo Mode**. Select **Use synthetic reference values** to verify the demo against the fixture manifest, or correct the fields yourself. Run QR Only on the standard QR fixture to exercise the real decoder. The PDF fixture has two independently rendered preview pages.

## Google Cloud and synthetic smoke test

1. Create or choose an approved Google Cloud project, attach billing and enable the Vertex AI API (`aiplatform.googleapis.com`). Fill `GOOGLE_CLOUD_PROJECT_ID` with the project ID. An empty value keeps Vertex unavailable.
2. Grant the workload principal permission to invoke Vertex. The predefined Vertex AI User role (`roles/aiplatform.user`) is a starting point. The principal also needs `serviceusage.services.use` on the quota project. [Vertex IAM documentation](https://cloud.google.com/vertex-ai/docs/general/access-control).
3. Use Workload Identity or the attached service identity in hosted deployments. For local development run `gcloud auth application-default login` and `gcloud auth application-default set-quota-project PROJECT_ID` on the host. For Docker, bind-mount only the generated ADC file read-only at an internal path and set `GOOGLE_APPLICATION_CREDENTIALS` in the web/worker service environment to that path. Keep the file outside the repository. [ADC documentation](https://cloud.google.com/docs/authentication/provide-credentials-adc).
4. When paid testing is explicitly authorized, enable `INVOICE_AI_LIVE_ENABLED=true`, refresh cached config and restart the queue worker. In the panel load **Standard invoice with fiscal QR** and **Multi-page invoice**. Run AI Only and QR + AI, then check the EU route, structured fields, reported usage, estimated cost and latency. A 404 fails the run with the EU availability error. A failed request never changes region or API. Turn live processing off after the smoke test.

## Components and measurement

- The internal `app/Modules/InvoiceReader` module contains the reading engine and its benchmark screen. `InvoiceReaderServiceProvider` registers `VertexAiProvider` as a text-only Laravel AI driver. `VertexInteractionsGateway` adds EU-only URL validation, ADC authentication, timeouts and request measurement while inheriting the SDK's request and response mapping. `GoogleAccessTokenProvider` obtains and encrypts cached short-lived tokens, refreshing ahead of expiry. No community runtime dependency is installed.
- `InvoiceExtractionAgent` defines the extraction instruction and schema. `InvoiceData` verifies shape and handles decimal/date and field comparison. `InvoiceQrCodeService` decodes on the host, inspects PDFs and rasterizes previews. Its parser follows the [AT fiscal QR specification](https://info.portaldasfinancas.gov.pt/pt/apoio_contribuinte/Novas_regras_faturacao/Documents/Especificacoes_Tecnicas_Codigo_QR.pdf). QR Only preserves identifiers, total tax, gross total and the published tax categories and amounts. The QR does not carry product details or numeric VAT rates.
- `InvoiceBenchmarkService` owns the private upload, immutable originals and queued per-document mode runs. A SHA-256 match reuses the retained upload for the same account and operator. QR + AI uses the valid QR fields for shared scalars, keeps the AI VAT breakdown when reported, and records disagreements. A QR lookup problem is visible even if the EU AI step succeeds.
- `InvoiceRequestMetrics` records each attempted Vertex POST with its response status, duration, reported numeric usage and pricing snapshot. It stores estimated USD as an exact decimal string. `InvoicePricingService` uses uncached input, cached input and output including reasoning. An explicit 429 with up to a three-second Retry-After can be retried once. Network and server failures are not retried because billing might have occurred. An absent or inconsistent usage report leaves the estimate unknown. Projections use complete observed API cost samples. Actual billing has not been reconciled with Google Cloud.
- `InvoiceBenchmarkDashboard` compares immutable results with the current verified values for the latest 100 retained documents. Totals and projections count run samples, with per-mode/model breakdowns. Demo results have their own group and do not contribute to observed extraction accuracy. A run is fully correct when all verified fields match. Correction rate is the share of verified runs with at least one mismatch or missing field. VAT groups are order-independent, line items are compared in document order, and comparisons skip unverified values. Document types and minimum fields are benchmark conventions, not a fiscal conformity ruling.
- The page, preview controller and pruning command handle review, authenticated previews and expiry. The worker and benchmark tables do not write to the real accounting workflow. Current limitations include one retained run per mode and document, a 20-page PDF limit, a bounded QR scan, and no provider-side actual billing import.

## Privacy before production use

Uploads and derived previews are private and excluded from file backups. Extracted content and ground truth are encrypted in the database. The scheduled cleanup deletes uploaded files, outputs and metrics together after expiry, so longer evaluation requires choosing a suitable retention window before uploading. Review existing database backups and their retention because database snapshots can retain encrypted benchmark data after deletion. Confirm backup locations and key management. Disable payload-capturing observability for uploads, AI events and outbound HTTP. Keep Poppler and ZBar patched and run the web and worker processes with minimal privileges.

Before real customer documents are used, confirm the Google Cloud DPA, service-specific processing and retention terms, data residency guarantees for the model and API, subprocessors and international transfers. Confirm lawful basis, retention, access controls and any required impact assessment for the application. The EU hostname and `store=false` address routing and interaction persistence only. [Google Cloud DPA](https://cloud.google.com/terms/data-processing-addendum) · [Interactions security and data residency](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/capabilities/interactions#security_and_compliance).

## Verification status

Focused Pest tests exercise HTTP-faked Vertex requests and ADC, local QR and PDF tools, preview authorization, expiry, upload deduplication, pricing and the Filament review workflow. No paid Google Cloud requests were executed. Live endpoint behavior in the configured project, extraction quality, latency, reported usage and billed cost still require the synthetic smoke test.
